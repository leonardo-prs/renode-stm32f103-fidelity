## Tempo virtual Renode (lib-2) — aceito
- Fonte canônica: Time framework (virtual time em segundos virtuais, res 1ns; periféricos vivem nele; host só tenta acompanhar; AdvanceImmediately = roda o mais rápido possível; default freia p/ não correr à frente, nunca garante acompanhar; CurrentLoad/CummulativeLoad, ElapsedVirtualTime)
- MIPS default 100, configurado por Monitor (.resc), NÃO no .repl STM32F1 (repl só tem systickFrequency/frequency de timers); quantum = tempo virtual entre sync phases (zero ilegal); determinismo via slave time sources; Robot opera no tempo virtual
- MIPS != clock MCU: diz instruções TCG por segundo virtual; pipeline/flash wait-states/clock tree não calibrados; issues #553 (HAL_Delay<1s, systickFrequency vs clock real, MIPS maior = delay parece mais longo) e #325 (1 MIPS != host) provam que calibrar MIPS até bater é overfit numérico
- Correto: MIPS/quantum como escalonamento da simulação (manter default 100 / 1us); calibrar só o físico (HSI 8MHz, prescalers TIMx, SysTick=HCLK/8); mensurando em ticks/ciclos (TIM2/DWT relativo) nos dois lados, nunca wall-clock; distribuições, nunca fator de correção
- tools/ útil: execution_tracer (Enable Tracing/Dump Trace + reader PC/opcodes c/ ts virtual), metrics_analyzer (ElapsedVirtualTime/loads), csv2resd (CSV→RESD p/ comparar trilhas), gdb_compare (funcional antes de temporal), sysbus LogPeripheralsAccess / cpu EnableExecutionTracing + hooks Python/C# (timestamping no domínio virtual); analyzers/ Roslyn irrelevante
